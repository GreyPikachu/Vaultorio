# Factorio P2P Cloud Sync & Coordinator («Сейф + Перехватчик»)

Децентрализованная система для комфортной кооперативной игры в non-Steam / standalone Factorio без сторонних VPN-утилит (Hamachi, Radmin VPN, Tailscale), с минимальным прямым P2P-пингом (15–25 мс) и автоматическим облачным хранилищем сохранений на личном сервере.

---

## 1. Архитектурная концепция

Традиционные подходы к совместной игре имеют фундаментальные ограничения:
- **Выделенный сервер на VPS в США/ЕС**: пинг 120–150 мс из РФ/РБ и высокое потребление ресурсов (500–1200 МБ ОЗУ), что недопустимо на легковесном VPS с личным VPN (Xray, Hysteria 2).
- **Прямой хостинг на компьютере одного игрока**: привязка мира к конкретному ПК; если владелец сейва оффлайн — друзья не могут играть.
- **Сторонние виртуальные сети (Hamachi, Radmin)**: требуют установки стороннего софта всеми игроками, часто вызывают сбои маршрутизации и увеличивают задержку.

### Решение «Сейф + Перехватчик»:
1. **Облачный «Сейф» на VPS**:
   - Мир хранится на сервере в виде атомарного архива `cloud_world.zip` с ротацией 3 резервных копий и проверкой SHA-256.
   - Сервер НЕ запускает headless-сервер Factorio. Потребление памяти составляет ~15–25 МБ ОЗУ (FastAPI + DatagramProtocol).
   - STUN-координатор на порту `14197/udp` обеспечивает определение публичных адресов и координацию прямого пробития NAT (UDP Hole Punching), находясь строго вне диапазона `20000:50000/udp`, зарезервированного для VPN Hysteria 2.
2. **Прозрачный клиентский перехватчик (FactorioWrapper)**:
   - Подменяет оригинальный `factorio.exe` (или `Factorio.app/Contents/MacOS/factorio`), переименовывая оригинал в `factorio_core`.
   - Игроки запускают игру как обычно, через стандартный ярлык.
   - Первый запустивший игру становится Хостом: перехватчик скачивает актуальный сейв, открывает сетевое лобби и координирует P2P.
   - Подключающиеся друзья автоматически становятся Гостями: сейв физически скрывается в `saves/.cloud_stash/` (защита от Split-Brain), адрес прямого подключения `127.0.0.1:34198` копируется в буфер обмена, и запускается локальный UDP-прокси.

## 2. Ключевые механизмы защиты

### 2.1. 4-фазная машина состояний сервера
Сервер управляет жизненным циклом сессии через строгий автомат состояний:
1. `idle`: сервер свободен, сейв готов к скачиванию первым игроком.
2. `claiming`: предварительная бронь роли Хоста (TTL 180 сек). Если игрок открыл главное меню, но не запустил сетевую игру, бронь автоматически аннулируется без перезаписи сейва («Защита от Фальшивого Хоста»).
3. `hosting_active`: Хост реально запустил сетевой мир (подтверждено по логу и сокету). Аренда продлевается каждые 30 секунд фоновым `heartbeat` (таймаут обрыва сети 90 сек).
4. `uploading_final`: Хост закрыл игру и выгружает итоговое сохранение на VPS (TTL 45 сек). Если второй игрок запускает игру в этот момент, перехватчик дожидается завершения выгрузки, гарантируя передачу самого свежего мира.

### 2.2. Защита от раздвоения мира (Split-Brain Shield)
- **Физическое скрытие**: при назначении роли Гостя файл `saves/cloud_world.zip` временно перемещается в скрытую подпапку `saves/.cloud_stash/`. В меню «Загрузить игру» Второй игрок физически не видит этот мир и не может случайно запустить параллельный хост. При закрытии игры или уходе Хоста файл возвращается обратно.
- **Криптографический токен**: сервер принимает выгрузку сейвов (`POST /upload-save`) только при предъявлении активного `session_token`, выданного текущему Хосту. Попытки неавторизованной выгрузки блокируются с кодом `403 Forbidden`.

### 2.3. Rolling Sync и защита от несохраненного прогресса
- В `config.ini` автоматически выставляется `autosave-interval=2` (автосейв каждые 2 минуты) и `non-blocking-saving=true`.
- Фоновый демон Хоста каждые 2 минуты выгружает свежие автосейвы на VPS.
- При выходе из игры перехватчик находит самый свежий файл между `cloud_world.zip` и последним `_autosaveN.zip` текущей сессии. Даже если Хост нажал «Выйти» без ручного сохранения, ни одна секунда прогресса не теряется.

### 2.4. Бесшовная передача эстафеты (Handover)
Если Хост выходит из игры, фоновый монитор у Гостя (`GuestHandoverWatcher`):
1. Фиксирует переход статуса сервера в `idle`.
2. Возвращает скрытый сейв и скачивает только что выгруженный актуальный `cloud_world.zip`.
3. Показывает уведомление о том, что прежний Хост вышел, и теперь игрок может запустить игру как новый Хост.

### 2.5. Stealth Mode и Коды Дружбы (`FCT1-...`)
- **Zero Open Ports для посторонних**: все рабочие HTTP-эндпоинты и UDP STUN закрыты проверкой постоянных токенов устройств (`X-Device-Token` / payload). Неавторизованные запросы молча отбрасываются (UDP) или отклоняются с `403 Forbidden` (HTTP).
- **Криптографические одноразовые инвайты**: администратор сервера генерирует зашифрованный «Код Дружбы» формата `FCT1-...` на базе PBKDF2-HMAC-SHA256 (100 000 итераций) + потокового шифрования CTR + HMAC-SHA256 (Encrypt-then-MAC) + zlib-сжатия. Код полностью скрывает адрес и порт сервера, предотвращая сканирование.
- **Одноразовая выдача `device_token`**: при первом запуске друг вводит код и кодовую фразу. Сервер гасит одноразовый билет и выдает постоянный токен устройства, сохраняемый локально в `factorio_sync_config.json`.

### 2.6. Динамическое чтение ника из `player-data.json`
- Никнейм игрока НЕ привязан жестко к конфигурационному файлу.
- При каждом старте перехватчик считывает текущий `"service-username"` напрямую из `player-data.json` Factorio.
- Если игрок поменял свой ник в настройках Factorio, при следующем запуске он автоматически авторизуется под новым ником без необходимости сбрасывать токен или перенастраивать клиент.

### 2.7. Графический онбординг первого запуска (`FirstRunSetupWindow`)
- При первом запуске игры (до настройки) поверх открывается темное окно в палитре Factorio Dark Industrial.
- Окно автоматически считывает локальный ник, позволяет вставить код `FCT1-...` из буфера обмена одной кнопкой и безопасно ввести пароль.
- После однократной настройки окно больше никогда не появляется: игра запускается мгновенно и бесшумно (0 консольных окон благодаря флагу сборки `--noconsole`).

## 3. Развертывание на VPS

Серверная часть устанавливается на личный VPS (`<YOUR_VPS_IP>`).

### 3.1. Требования
- Ubuntu 22.04+ / Debian 11+
- Python 3.10+
- Свободные порты: `8088/tcp` (HTTP REST API) и `14197/udp` (STUN Coordinator).
- Строгий барьер: порты `20000:50000/udp` не затрагиваются (зарезервированы под Hysteria 2).

### 3.2. Автоматическая установка
```bash
# Клонирование репозитория на VPS
cd /opt
git clone <URL_РЕПОЗИТОРИЯ> factorio-setup
cd factorio-setup

# Запуск скрипта установки
chmod +x deploy/vps/install_vps.sh
sudo ./deploy/vps/install_vps.sh
```

Скрипт установки:
- Создает изолированное виртуальное окружение `venv`.
- Устанавливает минимальный набор зависимостей (`fastapi`, `uvicorn`, `python-multipart`, `pydantic`).
- Настраивает правила фаервола UFW (`8088/tcp`, `14197/udp`).
- Создает и активирует systemd-сервис `factorio-hub.service` с ограничениями памяти (`MemoryMax=64M`).

### 3.3. Генерация одноразовых инвайтов администратором (Admin CLI)
Для добавления друга администратор сервера генерирует «Код Дружбы»:
```bash
# Генерация одноразового кода со сроком жизни 60 минут и кодовой фразой
python -m src.server.admin_cli create-invite --ttl-minutes 60 --passphrase "секретная_фраза"
```
Команда выведет готовый код вида `FCT1-...`. Этот код и кодовая фраза передаются другу.

Другие полезные команды администратора:
```bash
# Просмотр активных инвайтов и зарегистрированных устройств
python -m src.server.admin_cli list

# Отзыв доступа по ID устройства
python -m src.server.admin_cli revoke-device <DEVICE_ID>

# Очистка истекших инвайтов
python -m src.server.admin_cli prune
```

### 3.4. Управление сервисом
```bash
sudo systemctl status factorio-hub
sudo journalctl -u factorio-hub -f
sudo systemctl restart factorio-hub
```

### 3.5. Деинсталляция
```bash
sudo ./deploy/vps/uninstall_vps.sh
```

## 4. Установка для игроков (Windows и macOS)

### 4.1. Установка в один клик
1. Скачать готовый установщик `Factorio Coop Setup.exe` (Windows) или `Factorio Coop Setup` (macOS).
2. Запустить установщик:
   - Установщик автоматически находит директорию Factorio.
   - Заменяет бинарник на перехватчик, сохраняя оригинал в `factorio_core`.
3. Запустить игру через стандартный ярлык Factorio:
   - При первом запуске откроется темное графическое окно настройки.
   - Вставьте «Код Дружбы» (`FCT1-...`) и введите пароль.
   - Нажмите «Подключиться».
4. Всё готово! Окно настройки закроется, и начнется игра. При всех последующих запусках окно больше не появится.

### 4.2. Как играть
- **Первый игрок (Хост)**:
  1. Запускает Factorio обычным ярлыком.
  2. Видит уведомление: `«Вы — Хост! Зайдите в: Сетевая игра -> Запустить сохранённую игру -> cloud_world»`.
  3. Выбирает мир `cloud_world` и нажимает «Запустить».
- **Подключающиеся друзья (Гости)**:
  1. Запускают Factorio обычным ярлыком.
  2. Видят уведомление: `«Сейчас хостит Alex! Зайдите в: Сетевая игра -> Прямое подключение -> Подключиться»`.
  3. Переходят в меню: **Сетевая игра -> Прямое подключение -> Подключиться** (адрес `127.0.0.1:34198` уже предзаполнен и скопирован в буфер обмена).
  4. Подключаются к игре с прямым P2P-пингом (15–25 мс).

### 4.3. Удаление перехватчика
Запустить установщик повторно и выбрать откат. Игра мгновенно возвращается к чистому оригинальному состоянию.

```text
FactorioSetup/
├── deploy/
│   └── vps/
│       ├── factorio-hub.service    # Systemd-юнит с лимитом памяти 64 МБ
│       ├── install_vps.sh          # Скрипт установки на VPS
│       ├── requirements.txt        # Серверные зависимости
│       └── uninstall_vps.sh        # Скрипт отката
├── src/
│   ├── common/                     # Общие криптографические модули
│   │   └── invite_codec.py         # Кодек инвайтов FCT1-... (PBKDF2 + AES + HMAC)
│   ├── client/                     # Клиентское ядро перехватчика
│   │   ├── config.py               # Конфиг клиента, device_token, барьеры портов
│   │   ├── factorio_env.py         # Пути Factorio, Split-Brain Shield, player-data
│   │   ├── factorio_wrapper.py     # Точка входа перехватчика
│   │   ├── host_workers.py         # LobbyDetector, Heartbeat, AutosaveWatcher
│   │   ├── hub_client.py           # HTTP REST клиент Сейфа с поддержкой инвайтов
│   │   ├── p2p_tunnel.py           # HostP2PBridge, GuestP2PProxy, STUN хэндшейк
│   │   ├── session_orchestrator.py # SessionOrchestrator, HandoverWatcher
│   │   ├── setup_gui.py            # FirstRunSetupWindow (темный GUI первого запуска)
│   │   └── ui_notifier.py          # Буфер обмена и всплывающие подсказки
│   ├── installer/                  # Одноразовый установщик
│   │   └── installer.py            # FactorioWrapperInstaller (установка/откат)
│   ├── server/                     # Серверный модуль Сейфа и STUN
│   │   ├── admin_cli.py            # CLI администратора (создание инвайтов, отзыв)
│   │   ├── api.py                  # FastAPI REST роутер со Stealth Mode
│   │   ├── auth_manager.py         # Менеджер инвайтов и токенов устройств
│   │   ├── config.py               # Конфигурация сервера
│   │   ├── logger.py               # Ротируемый логер
│   │   ├── main.py                 # Точка входа сервера
│   │   ├── schemas.py              # Pydantic-схемы валидации
│   │   ├── session_manager.py      # SessionLockManager (4-фазный автомат)
│   │   ├── storage.py              # SaveStorageManager (атомарное хранилище)
│   │   └── stun_coordinator.py     # UDP STUN координатор (14197/udp)
│   └── testing_support/            # Средства тестирования и эмуляции
│       └── mock_factorio_core.py   # Имитатор движка игры
├── build/
│   └── build_client.py             # Скрипт сборки PyInstaller (--noconsole)
└── tests/                          # 250+ автоматических модульных и E2E тестов
```

## 6. Разработка и тестирование

### 6.1. Запуск тестового набора
Проект покрыт всесторонними модульными и сквозными тестами (250+ тестов, 100% прохождение):
```bash
# Активация виртуального окружения
source .venv/bin/activate

# Запуск полного набора тестов
pytest tests/ -v
```

### 6.2. Сборка standalone-бинарников через PyInstaller
```bash
# Сборка перехватчика и установщика без консольных окон (--noconsole)
python build/build_client.py --target all
```
Готовые бинарные файлы будут созданы в каталоге `dist/`.
